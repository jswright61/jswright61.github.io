I have been a Ruby developer for over 10 years. I learned Ruby for a job I started in 2014. That role involved maintaining and enhancing several web applications that were pretty evenly split between the Ruby on Rails and Sinatra frameworks. I left that role in 2017.

Since 2014, when I start a new project, whether it be a quick little script to automate a repetitive task, or a communications tool that I wrote to manage communication with the customers of our small business, I wrote my code in Ruby. I love Ruby. I am generally pretty efficient in solving the problem at hand with Ruby code. I've found a wealth of knowledge and help from the Ruby community. Whenever I ran up against a problem I didn't know how to solve I was able to find articles and other resources to get me to a solution.

To be perfectly candid, there were some things about Ruby that always bothered me, mostly having to do with style. To write "idiomatic Ruby" is to include parentheses in method calls only when required, and to make liberal use of dangling if statements: my_var = 123 if other_var > 5000. Which in Ruby is one line of code and the assignment only takes place if the conditional evaluates to truthy. Both of these customs, to this day, make it harder for me to understand code that makes use of them. My solution: I don't use them. This is one of the great things about Ruby, I don't have to and my code works fine.
